# ACCX Package Publication Procedure

The Python package is published as `accx`; the npm registry rejected the exact unscoped name `accx` because it is too similar to existing packages such as `docx` and `cpx`. Publication is an external, irreversible distribution action and is deliberately not run by normal CI or by ACCX application deployment. A scoped npm name, such as `@nexuss0781/accx`, must be selected before JavaScript publication can proceed.

Before publishing, an authorized maintainer must confirm the target version in both `packages/sdk-js/package.json` and `packages/sdk-python/pyproject.toml`, run the full release verification suite, inspect the npm dry-run file list, inspect the PyPI wheel with `twine check`, and review the security workflow results. Do not publish a package containing development secrets, test fixtures with values, `.env` files, local databases, or provider credentials.

The `Publish ACCX SDKs` GitHub workflow requires a manual dispatch, an exact version, the literal confirmation value `PUBLISH`, an approved `package-publication` environment, `NPM_TOKEN`, and `PYPI_TOKEN`. Configure those registry tokens only as protected GitHub environment secrets. The workflow verifies artifacts and matching versions before it calls either registry.

The PyPI `accx==0.1.0` release is publicly verified at https://pypi.org/project/accx/0.1.0/. The npm `accx@0.1.0` release was not published because the unscoped name was rejected. After the npm name is selected, install each package from a fresh virtual environment or Node project and submit only a reference-based test action to a non-production ACCX workspace. Record package versions, commit ID, release time, and sanitized verification result. Rollback means issuing a corrected later version and revoking compromised workload tokens; published package archives should not be altered.
